# Qwen3-0.6B LoRA comparison: final P4 results

## Run and artifacts

The three-epoch LoRA run and paired first-pass evaluation completed on a Tesla T4 in Colab. All **618 paired model outputs** and the associated `comparison_metrics.csv`, `summary.json`, `run_manifest.json`, validator failures and training logs are committed in this repository. The adapter and checkpoints remain in the team Google Drive at `HumanFirst-Route/qwen3_06b_lora_v1/training/adapter`; the manifest records SHA-256 hashes for the seven adapter files. Those hashes were verified against the supplied handoff archive. The original paired generation demonstrates that the adapter loaded in the original Colab run. A fresh CUDA load-and-generation smoke test was not performed in this workspace.

The pinned base is `Qwen/Qwen3-0.6B` at revision `c1899de289a04d12100db370d81485cdf75e47ca`. The run used 2,822 filtered training examples from 208 tasks and 599 development examples from 46 tasks. LoRA rank was 8, alpha 16, dropout 0.05, with three epochs, learning rate 1e-4, FP16 and effective batch size 16. Test evaluation contains 618 outputs over 41 task clusters.

## Paired validator and latency results

| Measure | Base Qwen | LoRA Qwen |
|---|---:|---:|
| Validator acceptance | 99.19% | 99.51% |
| Validator compliance | 99.35% | 99.51% |
| Leakage flags | 0.16% (1/618) | 0.00% (0/618) |
| Mean generation latency | 1.53 s | 2.62 s |

The paired acceptance difference was **+0.32 percentage points** (task-cluster bootstrap 95% CI: **−0.73 to +1.27 percentage points**). The interval includes zero; this run does not establish a reliable acceptance improvement. LoRA generation was about 72% slower on average. These are automated rule-validator and latency outcomes only. Validator acceptance does not establish factual correctness, hint quality, pedagogical usefulness, or learner benefit.

## Error analysis

The automated validator classified the 618 pairs as follows: 610 both pass; 5 base fails while LoRA passes; 3 LoRA fails while base passes; 0 both fail. `ERROR_ANALYSIS.md` separates rule-triggered cases from qualitative semantic concerns and validator limitations. Textual interpretations in that file are unblinded qualitative inspection only; they were not independently human-verified. Independent human evaluation was **not conducted**.

The validator primarily checks format/compliance and rule-based answer leakage. It can miss wrong or irrelevant advice and can flag valid prose. A passing result therefore cannot be interpreted as factual or pedagogical validation.

## Interpretation and limitations

Training targets were filtered hints, predominantly generated by the same base model. This is self-distillation rather than independent human-corrected supervision. Since the validator was already near ceiling for the base model, ceiling effects limit the metric's ability to distinguish systems. No independent human ratings were collected. No end-to-end test shows that LoRA fine-tuning improves unaided transfer or any real learner outcome. The defensible conclusion is limited to the observed first-pass rule-validator acceptance and generation latency on this held-out set; the confidence interval does not establish an acceptance advantage.
