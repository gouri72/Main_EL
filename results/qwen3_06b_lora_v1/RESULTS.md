# Qwen3-0.6B LoRA comparison: run summary

The full three-epoch LoRA run and paired first-pass evaluation completed on a Tesla T4 in Colab. The adapter weights and raw paired outputs remain in the team's Google Drive; only compact metadata and summary metrics are stored in this repository.

## Training

- Base model: `Qwen/Qwen3-0.6B`, revision `c1899de289a04d12100db370d81485cdf75e47ca`.
- Data: 2,822 train examples from 208 tasks; 599 development examples from 46 tasks.
- Configuration: 3 epochs; learning rate 1e-4; effective batch size 16 (micro-batch 1, accumulation 16); FP16; gradient checkpointing; LoRA rank 8, alpha 16, dropout 0.05.
- Runtime: Tesla T4; 4,954 seconds including final evaluation (about 82.6 minutes); train loss 0.0663; final dev loss 0.0692.
- A CUDA allocator warning appeared during training, but the run continued through all 531 steps and completed. See `training/training_metadata.json` for recorded versions and run details.

## Paired evaluation

Both models were generated on the same 618 held-out examples across 41 task clusters, with shared prompts, levels, generation parameters, and per-example seeds.

## Limits and remaining P4 item

Training targets were filtered hints from the existing bank, predominantly generated by the same base model. This is self-distillation; it is not human-corrected supervision. The experiment only supports a comparison on rule-validator outcomes and generation latency. It says nothing about learning gains or real learners.

Human relevance, correctness, level-fit and usefulness ratings remain pending. The 120-pair blinded sheet in the archive has no scores entered. The paired raw outputs and run manifest are now committed here, and the aggregate metrics have been independently regenerated from them. The adapter and training checkpoints remain in Drive.

The original annotation sheet records three dimensions and has one response area. The updated protocol creates two independent forms over the same blinded A/B pairs, adds usefulness, and reports quadratic weighted kappa for the four ordinal dimensions plus unweighted kappa for preference. No ratings or agreement values are reported until both human forms are returned and validated.

The actual example-level validator error analysis is now in [`ERROR_ANALYSIS.md`](ERROR_ANALYSIS.md). Across 618 pairs: 610 both passed; 5 had base fail and LoRA pass; 3 had LoRA fail and base pass; none had both fail. Direct text inspection identified likely semantic false negatives and a possible validator false positive, clearly separated from rule flags. These are qualitative assistant observations, not human ratings; a reviewer should verify them before calling them human-confirmed findings. A helper prepares blinded forms for that review.

## Paper-ready Results and Discussion

On 618 paired held-out outputs from 41 task clusters, LoRA fine-tuning yielded a rule-validator acceptance rate of 99.51%, compared with 99.19% for the pinned base Qwen3-0.6B model. The paired difference was +0.32 percentage points, with a task-cluster bootstrap 95% interval from −0.73 to +1.27 points. Since the interval includes zero and both rates are near ceiling, the experiment does not establish a reliable improvement in validator acceptance. Acceptance was descriptively higher for LoRA in coding (+0.37 points), science (+0.29), level 2 (+0.65), and level 4 (+0.65), and equal at levels 1 and 3. These are descriptive strata, not independent confirmatory tests.

LoRA outputs had a mean generation latency of 2.62 seconds, compared with 1.53 seconds for the base model (about 72% higher in this run). Training reduced loss on the filtered development targets, but those targets were predominantly base-model-generated pseudo-labels. Lower loss therefore indicates fit to the self-distillation targets; it does not demonstrate more factually correct or pedagogically effective hints. The rule-based validator measures only its encoded compliance and leakage rules. It does not judge semantic correctness, relevance, usefulness, or learning outcomes.

Human quality ratings are not yet available. The actual paired raw outputs reproduce the numeric summary, and the supplied adapter files match the hashes in the run manifest; the original evaluation successfully produced LoRA outputs. A fresh CUDA load test was not possible in this workspace. Accordingly, the comparison supports a narrow statement about first-pass validator outcomes and latency on this held-out set, with semantic error observations treated as unblinded qualitative inspection. It supports no claim about human learning, transfer, teaching effectiveness, or improved factual accuracy.
